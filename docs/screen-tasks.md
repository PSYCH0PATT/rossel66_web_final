## Ответы владельца (подтверждено 19.08.2026 — этот раздел главнее таблиц выше)

**Главный вывод — назначение админки.** Прямая цитата по смыслу: сайт нужен в первую очередь АРТИСТАМ; админка нужна для 1) аналитики по стримам, 2) создания квартальных отчётов, 3) просмотра «в какие плейлисты попали наши релизы», 4) правки профилей артистов. Большинство остальных функций админки — сервисные: чинить ошибки, чтобы у артистов всё правильно отображалось. Ручные операции запускаются «когда что-то ломается», а не ежедневно.

**Ядро админки (primary-экраны):** analytics, reports (+генератор), playlists, artists (карточки/правка профилей), dashboard как обзор.
**Сервисные экраны/функции (нужны, но «в жопе» — прячем в secondary/dropdown, не удаляем):** всё из списка ниже.

По вопросам анкеты:

1. Отчёты — да, квартальный цикл.
2. Парсеры Zvonko/Koala — ежедневный АВТОМАТИЧЕСКИЙ прогон по крону. Вручную — только когда крон ломается. Кнопки парсеров на поверхности не нужны.
3. «Привязать релизы» — владелец вообще не помнит, что это за функция; используется очень редко → глубоко в secondary.
4. unregistered-reports — вопрос не понят владельцем, уточняется (пока считать редким/сервисным).
5. Генератор отчётов — раз в квартал (но в квартальный период — важный).
6. Плейлисты — синк кроном; главное на экране — ПРОСМОТР. Ручные synс-операции — сервисные.
7. Выплаты — владелец предлагает ГРАМОТНО ОБЪЕДИНИТЬ экраны выплат и отчётов в один (продуктовый вердикт, учесть в ia-decisions).
8. Активность — сейчас почти не пользуется. Хочет вместо общей ленты видеть три типа событий: какие плейлисты добавились; артист подписал/ознакомился с отчётом; поломки (парсинг релизов не прошёл и т.п.). Остальные события не нужны → лента фильтруется/чистится.
9. Артисты в ЛК заходят. Приоритет их интересов: 1) аналитика (стримы), 2) треки/релизы — статусы, UPC-коды, 3) отчёты (раз в квартал). Артист-ЛК проектировать вокруг этого порядка.
10. Настройки — ничем не пользуется чаще раза в месяц.
11. Кандидаты «спрятать, но оставить» (demote, НЕ удалять): «Обновить данные» на дашборде; футер «сервис работает»; массовое добавление артистов; «Добавить артиста» (не используется!); «Добавить релиз» (не используется, но должна существовать); привязка релизов; ручной запуск парсеров; загрузка отчётов (важная, но редкая); загрузка CSV / синхронизация / сопоставление — вся эта категория используется только при поломках.

**Дополнение про релизы:** в сами релизы админ тоже заходит РЕДКО — только когда что-то ломается (поменять ссылку на обложку и т.п.). Некоторые кнопки там не трогаются вообще. Экран релизов в админке — сервисный, НЕ ядро; его primary — поиск/просмотр для диагностики, все действия — secondary.
