# Дизайн-аудит личного кабинета — ROSSEL Music

**Дата:** 2026-07-20
**Метод:** визуальный проход по браузеру под admin-сессией. Проверено ~15 экранов всех типов (дашборды артиста+админа, stat-cards, таблицы, формы, детальные, списки-сетки, графики, отчёты-табы, активность, настройки, пустые состояния) на mobile 375 и desktop 1280 + программные метрики переполнения + a11y-скан.
**Тема:** тёмная (светлой в кабинете нет).

> Область: только дизайн/вёрстка/адаптив/консистентность/доступность. Функциональные баги — в `AUDIT_FUNCTIONAL.md`, безопасность — в `AUDIT.md`.

---

## Резюме

Кабинет визуально **стильный и в целом аккуратный** на десктопе: тёмная тема, крупная типографика, читаемые таблицы и графики. Основные проблемы — в трёх плоскостях: **(1) консистентность** (смешаны русский/английский, разные форматы дат, разная раскладка KPI артист↔админ), **(2) мобильная плотность/адаптив** (огромные stat-карточки, переполнение кнопок, гигантские страницы), **(3) доступность** (нет фокус-индикатора, `lang="en"`, мелкие тач-таргеты).

### Топ проблем
1. 🟠 **Смешаны английский и русский по всему UI** (DS8) — «CONTROL PANEL», «LAST UPDATED», «VIEW ALL», «System Operational», «TOTAL FOUND: N PLAYLISTS», даты «May 14, 2026».
2. 🟠 **Нет видимого индикатора фокуса** (A11y) — `outline:none`, навигация с клавиатуры вслепую.
3. 🟠 **`<html lang="en">` при русском контенте** (A11y) — скринридеры читают русский с английской фонетикой.
4. 🟠 **Огромные stat-карточки на мобильном** (DS2) — до контента ~1700–2000px прокрутки.
5. 🟠 **Переполнение/обрезка на мобильном** — кнопки «Скачать все/Удалить» в карточке квартала обрезаются; иконочные табы без подписей.

## Дизайн-проблемы

### Каркас, тема, перф
- **DS1. Только тёмная тема, светлой нет.** `.dashboard-theme` хардкодит фон (`app/dashboard/dashboard.css:3` `--background:0 0% 4%`). `components/theme-toggle.tsx` существует, но подключён ТОЛЬКО к неиспользуемому демо `components/kokonutui/top-nav.tsx:49`; реальный навбар без переключателя. → Добавить светлую тему или убрать мёртвый toggle.
- **DS5. Тяжёлый фикс-фон бьёт по перфу на мобильном.** `app/dashboard/layout.tsx`: 3 больших блюр-блоба (`blur-[150px]`, один с `animate-pulse-slow-azure-blob`) + `grid-bg` + `noise-overlay`, всегда смонтированы. Большой blur + анимация на fixed-слое — джанк на мобильных (скролл-жесты таймаутили во время аудита). → Упростить/отключить анимацию на мобильном, уважать `prefers-reduced-motion`.
- **DS6. Вложенный скролл вместо скролла страницы.** Контейнер `h-[100dvh] overflow-hidden`, скроллит `main.overflow-y-auto`; тело не скроллится (`document.body.scrollHeight === innerHeight`). → Проверить сброс позиции прокрутки при клиентской навигации и квирки iOS (динамический тулбар/клавиатура).

### Консистентность
- **DS8. Смешаны EN/RU подписи (по всему кабинету).** Вживую: «CONTROL PANEL» и «LAST UPDATED» (сайдбар/дашборд), «CURRENT/TARGET» (легенда графика), «VIEW ALL» (лента), «System Operational» + «TOTAL FOUND: 0 PLAYLISTS» (плейлисты), «ROSSEL LABEL ENGINE V2.4 | ADMIN» (футер отчётов), метки «EMAIL»/«USERNAME». → Единый язык (русский).
- **DS9. Форматы дат несогласованы между экранами.** Релизы артиста: «May 14, 2026» (англ. локаль, `releases-client` formatDate `en-US`). Отчёты: «31.05.2026» (рус.). Лента: «06.05». Native date-инпуты: «мм/дд/гггг» (месяц-первый). → Единый рус. формат `DD.MM.YYYY` через общий хелпер (см. функц. A4).
- **DS10. Раскладка KPI несогласована артист↔админ.** Артист-дашборд: компактная 2×2 сетка (хорошо). Админ-дашборд и `/admin/artists`: 1 карточка в ряд, каждая почти на весь экран, число и бейдж-дельта разнесены большим пустым полем (`main` 2767px на artists). → Привести админ к компактной сетке.
- **DS7. Фейковые дельты и «TARGET» подрывают доверие (дизайн + функц. C5).** Видны `+426`/`+2`/`+4`/`+5.4%`/`+0`. Легенда «CURRENT/TARGET» на графике, где TARGET бессмыслен. → Считать реально или убрать.

### Мобильная адаптивность
- **DS2. Огромные stat/KPI-карточки на мобильном → избыточная прокрутка.** `/admin/artists`: 3 карточки (~1700px) до списка; админ-дашборд: 4 карточки на весь экран. → Компактный вид на мобильном.
- **DS11. Переполнение кнопок в карточке квартала (отчёты).** На `/admin/reports` кнопки «Скачать все» (зел.) и «Удалить» (красн.) не влезают по ширине — «Удалить» обрезано справа. → Перенос/стек кнопок на мобильном.
- **DS12. Иконочные табы и фильтры без подписей.** `/admin/reports`: таб-бар — 3 голые иконки (документ/зачёркнутый штамп/загрузка); фильтры «$» и «⊗» без подписей — неясно, что делают. `/admin/artists`: кнопки добавить/массово — только иконки. → Подписи/тултипы.
- **DS3. Заголовки страниц переполняются на узких вьюпортах.** Огромный display-шрифт не ужимается: `/admin/playlists/parsers` «ПАРСЕРЫ ПЛЕЙЛИСТОВ» обрезается. → `clamp()`/перенос.
- **DS13. Гигантские одностраничные экраны.** `/admin/playlists` = **9176px** на мобильном (всё на одной странице: табы + фильтр + 26 карточек + панели). Долгая прокрутка, тяжёлый ререндер (см. функц. F-PARS-12 вложенный компонент). → Разбить на роуты/ленивую загрузку.

### Мелочи/наименование
- **DS14. Внутренние понятия в UI.** Таб «ПАРСИНГ (РЕЗЕРВ)» на плейлистах выносит «резерв/дубль-страница» наружу (см. функц. F-PARS-5). Футер «ROSSEL LABEL ENGINE V2.4» — дев-флейвор. → Убрать/переименовать.
- **DS15. Админ не может смотреть аналитику артиста.** `/dashboard/artist/[username]/analytics` при роли admin делает `router.push('/dashboard/admin/dashboard')` — в отличие от всех других артистских экранов, которые админ видит. Несогласованность (дизайн+функц.).

## Доступность (a11y)
- **A11y-1. `<html lang="en">` при русском контенте** — скринридеры используют английскую фонетику. → `lang="ru"`.
- **A11y-2. Нет видимого индикатора фокуса.** У кнопки в фокусе `outline-style:none`, `box-shadow:none` — навигация с клавиатуры вслепую (WCAG 2.4.7). → Добавить видимый focus-ring.
- **A11y-3. Мелкие тач-таргеты.** 11 из 37 интерактивных элементов <40px (иконки, тоглы) — ниже рекомендованных 44px. → Увеличить/добавить hit-area.
- **A11y-4. Изображения без `alt`.** Логотипы (2/2 img) без alt. → Добавить alt/`aria-hidden` для декоративных.
- **A11y-5 (проверить).** Контраст приглушённого серого текста на тёмном фоне местами бледный (подписи-хелперы) — не измерял ratio; проверить на соответствие 4.5:1.

## Что сделано хорошо (не трогать)
- Десктоп-таблицы (Выплаты) и графики читаемы и аккуратны.
- Сетка артистов (2 колонки) и артист-дашборд (2×2 KPI) на мобильном — компактно.
- Аналитика (линейный график + список «Платные/Бесплатные») адаптируется без горизонтального переполнения.
- Формы (добавление релиза, настройки) на мобильном — полноширинные поля, обязательные с красной звёздочкой, понятные плейсхолдеры.
- Пустые состояния (плейлисты, релизы) — с иконкой и описанием; инструктивные баннеры (отчёты, выплаты) — полезные.
- Горизонтального переполнения страницы (`scrollWidth > innerWidth`) на проверенных экранах нет.

## Осталось проверить (для 100% дизайн-покрытия)
Проверены типы экранов, но НЕ каждый из ~35 и не на всех брейкпоинтах:
1. **Планшет 768** — не тестировался (между mobile и desktop сетки могут ломаться).
2. **Не открытые экраны:** `admin/artists/add|bulk-add|[id]` (большая форма 794 стр.), `admin/releases|[id]|koala-parser|zvonko-parser`, `admin/playlists/parsers|history`, `admin/reports-generator`, `admin/unregistered-reports`, вложенные `admin/artists/[id]/*`, `login`.
3. **Модалки/диалоги** (назначение плейлиста, подтверждения удаления, предпросмотр отчёта) на мобильном — размер, скролл, кнопки.
4. **Интерактивные состояния:** hover/active/disabled, тосты (sonner), скелетоны при загрузке, состояния ошибок форм.
5. **Контраст** — измерить ratio приглушённого текста; **клавиатурная навигация** сквозь всю страницу; **скринридер**.
6. **Длинные значения** (очень длинные имена артистов/треков, большие суммы) — переполнение в карточках/таблицах.
7. **Светлая тема** в рендере (если будет вводиться).
