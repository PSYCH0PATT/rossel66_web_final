## Есть сейчас: `components/ui/`

Управляется CLI shadcn (`npx shadcn add <name>`), экспортная поверхность — контракт.

| компонент | заметка |
|---|---|
| `button` | канон для всех действий. Варианты добираются в 2.2 |
| `input`, `textarea`, `label`, `checkbox`, `switch` | базовые поля |
| `select` | дефоркнут по цвету на 2.1: сырые rgba заменены токенами |
| `dialog`, `popover`, `dropdown-menu`, `tooltip` | канонические, фон берут из темы |
| `table` | сырой примитив. Пресет DataTable поверх него — в 2.2 |
| `card`, `badge`, `alert` | основа для StatCard / StatusBadge / Banner |
| `skeleton`, `progress` | состояния загрузки |
| `tabs`, `command`, `calendar` | вспомогательные |
| `admin-input`, `admin-select` | ⚠️ **параллельная система, под ликвидацию (C-17).** В новом коде не использовать |

## Появится в этапе 2.2

Ничего из списка ниже пока не существует. Если ревью видит на экране самописный аналог —
это и есть находка: писать одноразовую версию вместо ожидания компонента не нужно.

| компонент | закрывает | назначение |

| **Pagination** | C-06 | счётчик в одном месте, «На странице», авто-скрытие при ≤1 страницы, RU-строки |
| **SegmentedControl** | C-07 | переключатель периода/режима (сейчас — ряды пилюль вручную на обеих аналитиках) |

| **ChartTooltip** | C-09 | компактный, флип у краёв, закрытие по тапу/скроллу. Заменяет 3 самописных тултипа |
| **EmptyState** | C-14 | иконка + текст читаемого контраста + **одно** действие |
| **Spinner** | C-14 | вместо `.animate-spin` по месту |
| **SectionHeader** | C-15 | один стиль заголовка секции |
| **StatCard** | C-15 | значение/подпись/акцент по правилу |
| **StatusBadge** | C-15 | поверх `ui/badge` + `status-*` токены. Сейчас статусы расходятся между /reports и /payments (F-23) |

Плюс два компонента добираются из shadcn CLI, а не пишутся:

| компонент | закрывает | зачем |
|---|---|---|
| `ui/sheet` | C-12 | мобильный drawer навигации — сейчас без скролла |
| `ui/scroll-area` | C-11, C-12 | видимый скроллбар там, где скролл остаётся |

Варианты `ui/button`, которые добираются в 2.2 (C-02): `cta` с glow,
`destructive-outline`, success/warning-outline через токены, плюс единый — реально
приглушённый — disabled.

## Куда что ставится (из вердиктов lk-cro)

Размещение задано в [docs/ia-decisions.md](../../docs/ia-decisions.md); здесь только
скелет, за деталями — туда.

- **PageHeader** — вершина каждого экрана, в слоте `actions` ровно один primary.
- **Toolbar** — под шапкой на списочных экранах; сервисное уезжает в overflow.
- **StatCard** — ряд метрик над основным содержимым; главная метрика экрана одна.
- **DataTable** — основное тело списочного экрана, строка кликабельна целиком.
- **Pagination** — под таблицей, скрывается при одной странице.
- **EmptyState** — вместо тела таблицы, не поверх него.
- **Banner** — над содержимым, сворачиваемый.

## Продуктовое решение, влияющее на состав экранов

По вердикту 0-а владельца **«Выплаты» и «Отчёты» объединяются в один экран**: сущность
у них одна — квартальный отчёт с жизненным циклом «загружен → ознакомился → подписал →
выплачено», сейчас разрезанным на два админ-экрана с третьим дублем в карточке артиста.
Компоненты для объединённого экрана берутся из того же словаря; отдельного «PaymentCard»
не заводится.

Под удаление (и потому в baseline не снимаются): `/dashboard/admin/unregistered-reports`
и визитка `/dashboard/artist/[username]`.
