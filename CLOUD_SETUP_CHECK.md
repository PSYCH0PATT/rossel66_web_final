# Задача: проверить, что проект заводится в этой облачной сессии

Ты — первая сессия проекта в облаке. **Задача одна: проверить среду и доложить.** Работу по редизайну НЕ начинать, код приложения НЕ менять.

Репозиторий: `PSYCH0PATT/rossel66_web_final`, ветка **`redesign/design-system`** (убедись, что ты на ней).

## Что сделать

**1. Зависимости и сборка**
```bash
pnpm install
pnpm verify --fast
pnpm build
```

**2. База и тестовый стенд.** Подними по порядку — что сработает, то и оставь:
- `docker compose -f docker-compose.test.yml up -d` (в облаке Trusted-доступ включает Docker Hub)
- если реестр даёт `Forbidden` — не мучай докер: `service postgresql start` (PostgreSQL 16 предустановлен), создай базу и пользователя с кредами из `docker-compose.test.yml` (rossel / rossel / rossel_test) на порту **54329**

Затем:
```bash
pnpm test:db:migrate
pnpm seed:e2e
```

**3. Тесты**
```bash
pnpm test
pnpm test:integration
npx playwright test --grep @smoke
```
(один `test.fixme` в smoke — известный, это B-05 из `docs/baseline-issues.md`, не чини)

**4. Скриншот-инструмент**
```bash
pnpm visual:baseline --routes /dashboard/admin/dashboard --out screens/check
```
Проверь, что скрины реально получились (файлы на диске, не нулевого размера). Если логин в скрипте не проходит — значит не хватает переменных или сида, это в отчёт.

**5. Документы на месте.** Проверь, что существуют и читаются: `PROMPTS_PLAYBOOK.md`, `docs/ui-audit.md`, `docs/ia-decisions.md`, `docs/screen-tasks.md`, `docs/ui-visual-findings.md`, `docs/baseline-issues.md`, `AGENTS.md`, `.claude/context/`, `.claude/skills/`.

## Что доложить (одним сообщением)

1. **Работает / не работает** — по каждому из пяти пунктов, с фактическим выводом команд, а не пересказом.
2. **Чего не хватает от владельца** — конкретным списком: какие env-переменные нужно добавить в настройки облачного окружения (по именам, из ошибок, а не из догадок), что ещё.
3. **Как поднимался стенд** — докер или нативный постгрес.
4. **Готово ли начинать план** — да/нет.

- Код приложения не менять. Можно: чинить конфигурацию среды, ставить пакеты, писать в `docs/baseline-issues.md`.

- Не начинать никакие пункты плана из `PROMPTS_PLAYBOOK.md`. Их владелец запустит отдельными сессиями.
